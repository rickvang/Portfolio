## Gaps and evolution

Bulk editing, arbitrary entity CRUD, autosave and a shared drawer-based editor are not established by this inventory. A request needing them selects extension or redesign; it must not silently turn an observed post implementation into a universal convention. A behavior-preserving cleanup selects refactor and checks current consumers. Existing component inventories and source imports are starting points, not an exhaustive dependency graph.

For a new or changed record, keep its scoped ID, owner, status (`observed`, `proposed`, `adopted`, `superseded`), retrieval cues, user problem, applicability/exclusions, relevant states, source revision/example, rationale/evidence and known consumers together in the existing owning reference. A proposal links its work record and baseline; adoption records the actual decision and checks. A replacement links both directions and tracks unmigrated consumers. Do not mark an old pattern superseded while remaining consumers still depend on it without a documented compatibility/migration disposition.
